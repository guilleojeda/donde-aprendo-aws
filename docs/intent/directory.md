# Directory behavior

The public directory helps visitors discover Spanish-language AWS learning resources and communities. It displays the approved titles, descriptions, legacy category values, and exact outbound URLs, including their query strings. The build does not invent missing descriptions. The short homepage links to dedicated **Aprender** (`/aprender/`) for individual articles, videos, courses, episodes and tools, **Creadores y canales** (`/creadores/`) for continuing sources such as blogs, channels, podcasts and newsletters, **Comunidades** (`/comunidades/`) for groups and community spaces, and **Eventos** (`/eventos/`). It shows up to four recommended resources and the next three events instead of the full catalog. Existing `/#resource-<id>` and `/#event-<id>` links route to the new page and reveal their card. AWS User Groups and Student Builder Groups are distinct community formats. Kind, format and up to three topics are separate DynamoDB fields. Search and format/topic controls operate in the browser on each resource page; supported filters and sorting are represented in shareable query parameters and restored by browser history. On certification study, **Ordenar por** shares the desktop row with **Examen o tipo de recurso**, above additional filters, and stacks with it on narrow screens; the result counter remains with the results. Results reveal twelve cards at a time with a further twelve per click. All published links remain in the generated HTML without JavaScript. Resource-directory pages stay at or below 2,000,000 raw HTML bytes, a conservative crawl-size bound enforced by site verification; every published card and description remains in the static page.

`/comunidades/` remains the complete directory, including its legacy `?country=XX` filter and `#resource-<id>` anchors. At build time, each supported country with at least one published community whose country is known gets a static `/comunidades/<slug>/` page. A fixed country-code-to-slug map keeps these URLs readable and stable; the pages use the same cached public catalog snapshot as the other routes and the sitemap. Each page contains only that country's communities in its initial HTML, with its own title, description, canonical URL, Inicio → Comunidades → country breadcrumb, and a factual summary of its community-format counts, including Student Builder Groups. Search, format and topic filters, sorting, and show-more work within that subset; changing country navigates to another page. The global and country pages include brief FAQs about participating in a community and finding its events, alongside guidance about the community formats. The count summary uses the same published subset as the cards; the result counter continues to reflect interactive filters. The collapsed native country menu keeps links to generated country pages in the HTML without taking space from results. New internal links to a community use its country page and stable card fragment when country is known; communities without a known country retain `/comunidades/#resource-<id>`. The homepage's older hash redirect continues to target the general directory for backward compatibility.

When visitors reveal more directory results, focus moves to the first newly
revealed card, including the final batch that removes the reveal button. The
next Tab reaches that card’s link. Normal initial rendering, filters, sorting
and restoring URL state do not move focus to a result automatically.

The global `/buscar/` page searches blog articles and published catalog resources together from a static public index generated at build time. It also includes active deduplicated events. Ranking requires every meaningful query word and favors title, topics and article headings over incidental description or metadata mentions; common Spanish connecting words do not skew results. Its query is intentionally not shareable in the URL so Analytics and HTTP referrers cannot carry the typed text; the directory-specific filter URLs remain shareable.

A search submitted with only whitespace clears its prior results and pagination
and shows the empty-query guidance. A previous asynchronous search cannot restore
those results afterward. Revealing more search results focuses the first new
result link; the initial search response leaves the visitor’s focus in place.
The initial public-index download has a bounded wait, including reading its
response body. A stalled or failed download shows the existing retry guidance
and clears the failed request even when its original query is no longer current.
The next submitted search can retry immediately; successful downloads remain
cached for subsequent searches on the page. Only the latest submitted query
can replace results or status.

`/recorridos/` provides four editorial sequences for fundamentals, serverless, security and generative AI. Each step resolves a published learning resource or a blog article to its existing internal destination; it does not copy that content. The paths are also available in global search. See [learning paths](learning-paths.md) for the editing contract.

**Agenda de eventos** at `/eventos/` contains published past, in-progress and future events, sorted by start time. The homepage preview and global search remain limited to upcoming/in-progress events. An event is a published catalog item with `recordType=event`, title, description, `startsAt` and `endsAt` as ISO timestamps with explicit offsets, IANA `timeZone`, organizer, mode (`online`, `in-person`, or `hybrid`), place for physical events, and `registrationUrl`. Only projected public fields reach the page. The agenda initially reveals twelve deduplicated cards, with more available through Mostrar más; all route events and their links remain in the generated HTML without JavaScript.

Every global, national and mode agenda opens with **Incluir eventos finalizados** checked. The checkbox stays local to the current page session: filtering, clearing, pagination and browser history preserve its current value, while opening/reloading starts checked again. It is not stored or serialized in the URL. `endsAt <= now` means Finalizado; an earlier start with a later end means En curso. The selected cards, count and fact summary update at start/end boundaries and on return to a visible tab without moving focus. With the checkbox checked, ending changes the state and original link label to **Ver evento** instead of removing the card. Inscribirme remains for upcoming/in-progress events and is the only action that emits the existing `event_registration_click` with public ID/mode/country; a historical page visit is not counted as a registration. Finalizado describes scheduled time, not proof of attendance or realization.

The complete filtered selection drives the count and summary before pagination. Every agenda opens on the current week, with **Semana / Mes** and previous/next arrows replacing the custom date range. Weeks run Monday–Sunday and months follow the calendar. A public event belongs when any part of its duration overlaps the period in the selected IANA zone: `startsAt < periodEnd && endsAt > periodStart`. An event ending exactly at the beginning is excluded; an event continuing into the period is included. One occurrence can therefore appear in consecutive periods, once in each.

The browser detects the initial zone, falling back to UTC when invalid; **Zona horaria** in Más filtros changes it explicitly. Primary dates, hours, period limits and the next-event summary all use that zone. The organizer schedule remains a separate reference. Calendar navigation uses civil dates, including daylight-saving transitions. A reference `date=YYYY-MM-DD` remains inside the period when switching views or zones; it is not forced to Monday or day one. Month navigation clamps a missing day to the last day of the target month. The current open period stays fixed at midnight and on return to a visible tab.

The URL records `view=week|month`, the concrete reference date and `tz=IANA`, plus mode, organizer country, community and verified event city. Browser history restores period, zone and these filters while keeping the local checkbox. Clearing filters keeps period, zone and checkbox. Legacy `from`/`to` opens the week of the first valid date (`from`, otherwise `to`) when no explicit valid date is supplied; the old range is then removed. Malformed calendar input normalizes without breaking the page, preserving unrelated query parameters. Invalid query zones use the detected valid zone, otherwise UTC. An empty period keeps its valid filters and navigation without jumping to another period. Navigation links between agendas preserve period and zone, including when opened in a new tab, and retain compatible facets while the destination supplies its route restriction.

Visitors can combine event mode, organizer country, community and verified event city with either period. On mobile, these filters and the zone control use the native **Más filtros** disclosure; active secondary URL filters open it. A community with future events keeps its `/eventos/?community=<id>` link. City remains optional, from structured `addressLocality` or a verified manual entry, never a group name or free-text venue. Country and mode retain their existing organizer/published-mode meanings. The static HTML contains every public occurrence for the route with organizer times and links; JavaScript applies the visitor's period, zone and filters, and the no-JavaScript notice explains this difference. Canonical URLs remain route-based; query combinations do not create extra static pages.

The agenda groups complete public occurrences, then chooses a member that satisfies the route, period and filters together. It retains all co-hosts, preferring a matching in-progress/upcoming member over an ended one, then sorting by start/ID. Displayed facts, original URL and calendar download belong to that member; it does not invent a combined interval. Upcoming wrappers filter ended members before grouping so the homepage/search representatives do not become historical. Every public ID, including a co-host and an ended event, has its own static `.ics` using its own UID, UTC instants and original registration URL. A download is a one-time copy, not a subscription; it changes with later builds and is removed when its record is unpublished.

A fragment for any public member reveals and focuses its group, including past cards and later batches; it activates the checkbox when needed and releases only incompatible filters. If the event is outside the period, the agenda opens the period of its start in the selected zone, preserving the view and showing the resulting period. It uses replaceState and keeps the fragment and unrelated query parameters. A fixed national/mode route that cannot contain that ID goes to the global agenda. Unknown/unpublished IDs do not create content. A published learning resource's optional `eventId` links its recording inside the corresponding event card; the separate recording archive is removed to avoid duplicated events/fragment IDs. The recording remains searchable and available in Aprender. The public contribution form continues to collect resource submissions; event curation uses DynamoDB and the approved Meetup sources.
Community options carry the published country of their community resource: the global country filter hides and clears communities from other countries, while a national agenda lists only communities from that country. All known co-host communities remain in each event card's data even when the event appears as one deduplicated card.

Revealing more events moves focus to the first newly visible event card, even
when the final batch hides the reveal button. Tab continues to that card’s
links. Global, national and mode agendas share this behavior. Filter changes
and automatic start/end updates do not move focus to a new card; explicit
event hash navigation keeps its reveal-and-focus behavior.

Physical listings with the same title, start instant and organizer country are
only grouped by session when their normalized venue matches and their known
cities agree. An omitted city can match a known city, but cannot connect two
conflicting cities through a shared group. Online session grouping is unchanged.
A shared canonical registration URL plus the same start instant remains a stronger identity for cross-posts
and co-hosts, including organizers in different countries. Reusing that URL at a different start creates a separate occurrence; equivalent timestamp offsets do not. Separate physical
sessions retain their own card, registration link and calendar download across
agendas, homepage previews and search.

The fixed `/eventos/online/` and `/eventos/presenciales/` collections use the published `mode` field. Online pages include online events; presenciales include both in-person and hybrid events. Group occurrences before selecting the collection, then choose a matching member while retaining the full co-host group and its aliases. Date, country, community and city filters remain inside that mode collection after clearing filters or restoring browser history. Published ended events follow the same mode subset and checkbox. Each event page includes concise FAQs about access or place, registration, time zones and calendar downloads as appropriate to the page; they do not add FAQ schema.

Every country with a published community has a stable `/eventos/<slug>/` agenda from the same catalog snapshot, including countries with no upcoming dates. The fixed country-code-to-slug map keeps community/event URLs readable. A national agenda includes a public occurrence when a member names that organizer country and displays a matching member, with complete co-hosts and aliases preserved. The route has its own title, description, canonical URL, breadcrumb, country navigation and mode links. Its community summary and related links remain available even for an empty selection. Country pages do not expose a country filter; visitors navigate between country pages. The global country filter retains published community countries and co-host countries represented by public events, including historical ones; an empty result is not reset to all. An event-only country with no generated community page keeps a working global event fragment. Legacy country queries, co-host fragments, `.ics` links and home hash routing remain useful.
The homepage provides five brief, always-visible answers for learners before the recommended resources: where to start without AWS experience, how to find Spanish-language courses and videos, how to find communities by country, where to consult upcoming events, and whether using the directory is free. These answers link to the existing learning path and directory sections and remain available in static HTML without JavaScript. Free use of the directory does not imply free external resources or free AWS service usage. The separate contributor FAQ stays beside the contribution form and explicitly states that adding content is free.

## Content ownership

DynamoDB is the single authoritative catalog. Site templates, assets, and blog article files belong in Git. Approved catalog records are not copied into Git for ongoing editing. The versioned Latin American Meetup directory is a reviewed seed for the initial import; it does not override later edits to the live catalog.

The directory does not accept payments or sponsorships. Recommendations are selected manually by the owner; the `featured` flag records that choice. Only articles in this site's blog are own content. The owner's channels and other resources are ordinary catalog resources and receive the same treatment as other entries. Each resource directory states this policy in its selection explanation and links to the blog. This native disclosure sits below the results and their reveal-more control, including empty-result states, and is closed on initial load. The `#directory-criteria` anchor targets the disclosure itself so a shared URL does not automatically expand its contents; visitors can open it when needed.

The initial migration created 95 supplied entries with the Boolean `published=true`; 12 more were approved later. The type migration classified those 107 records and changed only `kind`, `format`, and `topics`. The original `category` field remains for compatibility, but it does not control the new directory filters. Legacy records without the new fields are classified at build time so they remain visible during migration; incomplete explicit taxonomy is a build error. Reimporting an old export does not overwrite existing records, their content, or their publication flags. The 233 reviewed Spanish-language Meetup groups are imported with distinct IDs and conditional writes, so rerunning their import preserves live edits. Removed groups are separately unpublished in DynamoDB; the hourly event sync ignores Brazilian and Jamaican groups.

The discovery pass repaired seven empty descriptions and four moved links, and hid one duplicate Spotify listing for the podcast whose own site remains published. The hidden record stays in DynamoDB for review. The 12 resources added on 2026-09-25 have that verified `addedAt` date; older migrated records have no invented date. **Añadidos recientemente** shows only records with a known date. Sorting by recency puts undated records after dated ones. **Recomendados** uses the editorial `featured` flag. Each of the three directories explains in native HTML that **Recomendado** identifies a manual editorial selection. A known `addedAt` appears as **Agregado al directorio** with a Spanish date in UTC; it means incorporation into this directory, not original publication or later update. A missing date stays absent. The country field means the known country of the creator or organizing community, not an AWS region; level applies only to individual learning content. Both fields are optional and are shown only when supported by a source. A level is orientative for the topic and stated prerequisites, not a certification; a missing level is unassigned. An editorial link check establishes reachability at the check time only; it does not certify that instructions remain current, so no permanent verified badge is shown. Resource cards do not publish link-check or content-review dates. Country, level, format and topic filters can be combined.

Optional `sourceId` and `communityId` values point to existing catalog IDs. A displayed **Autor o fuente** relationship can identify an author, channel, or publishing organization through its published source record; it is not inferred from the destination host. When the referenced source or community is published, the content card links to its directory card; a hidden or missing target is not linked. Deep links reveal cards even when another section was selected. The build projects only these public fields and never private contributor contact details.

Only records with a Boolean `published=true` can appear in public output. Missing or false flags are unpublished; malformed publication values must not accidentally expose a submission. Public output is constructed from explicit allowlists of resource and event fields, never by serializing a database item that may contain submitter contact details.

The build must consume every scan page using strongly consistent reads so an approval completed before the scan begins is visible. Failed or malformed reads stop publication instead of producing a partial or empty catalog. A successful read with no published entries is a valid empty state. DynamoDB scans are not atomic snapshots of edits made during a multi-page read; a later hourly check can republish a changed hash.

## Publication

The site is a static snapshot. An hourly Lambda hashes the approved public catalog and starts a fresh Amplify build when it differs from the last successfully deployed hash. A second hourly Lambda reads each approved Meetup group's public iCalendar feed and structured data for unsuppressed, non-cancelled entries still observed there, then updates their DynamoDB records. Feed/page failures keep the existing protections for that group's prior events and raise an alarmable error; healthy sources can still update. When data changes, the sync invokes the publication checker; its own hourly schedule still handles manual approvals. The hash also includes whether each event has passed its end time, so the next hourly check rebuilds the static page after an event expires without a database edit. Retaining the catalog record does not stop this transition: the homepage and search still remove ended events, while the agenda updates their state and retains them when its checkbox is checked. Published recordings remain available through Aprender and their event cards. A Git deployment also reads the current catalog. Unpublishing follows the same rule; changing the flag does not instantly erase already-deployed HTML or external caches. The publication state lives in the reserved `__system#publication` item of the same DynamoDB table and is not a public resource. The Lambda records the hash only after Amplify reports success, checks for active builds before starting another, and raises an alarmable error when its build fails. An owner can still request an immediate build with `npm run publish`.

Meetup events retain their existing publication permission when their scheduled end passes, including when they subsequently disappear from a healthy feed. `published` authorizes public exposure; `endsAt` determines whether an event has finished. No separate archive or persisted lifecycle state is needed. For an existing ended Scheduled/Rescheduled event, source facts can be refreshed without writing `published`, so neither a hidden historical record nor a concurrent publication edit is restored. Unchanged observations do not cause hourly rewrites. An ended event without an existing record is not imported, and previously hidden historical rows are not automatically republished because the old flag cannot establish why they were removed.

Explicit feed/page cancellation, other valid nonpublishable page statuses, a future event missing from a healthy feed, and removal of its community from approved sources still unpublish events. Explicit cancellation and source removal also apply to historical records. `autoSync=false` prevents source edits; editorial suppression remains `autoSync=false` plus `published=false`. Writes retain source-ownership and sync guards, and absence-based retraction checks the observed end time to avoid overwriting a concurrent reschedule. There is no global ordering guarantee between simultaneous ingestions. Historical pages no longer exposed in feeds are not all crawled again: this retention preserves known permission and facts, not proof that an event occurred or a complete archive with guaranteed later cancellation detection.

Visitors submit contact details, title, URL, description, kind, format, and optional topics through the owned form. The API validates them, conditionally creates a catalog record with `published=false`, and confirms receipt only after DynamoDB accepts the write. A successful response includes the stable record ID and submission timestamp for the visitor's receipt, but no private contact data. The form explains that publication depends on editorial review; duplicate exact URLs, including pending submissions, are rejected without changing an existing record. The API temporarily accepts the old `Category` payload from already-deployed pages. The record also contains private submitter name and email fields for the owner's review. The build's projection excludes those fields even after approval. Newly approved entries default to order zero and appear after the imported records; the owner can edit their order directly.

The contribution form visibly explains that submitter name and email are stored
for reviewing the contribution and excluded from the public directory. It links
to the existing contact mailbox for requests to delete those details; requests
are handled by the owner, not an automated deletion endpoint. The notice does
not invent a retention period. When JavaScript is disabled, native HTML explains
that it must be enabled to send the form. The normal JavaScript validation,
submission and receipt flow stays available.

Resource and event cards offer a contextual email draft for a broken link or incorrect data. The draft includes only the public title, record ID and destination URL; the visitor must send it from their own mail client. A generic footer link covers pages without a card. This reuses the existing contact mailbox and does not create a second submission or moderation store. Editors investigate these messages and correct the authoritative DynamoDB record, or the versioned article file when the report concerns an article.

Footer text and links remain readable against their background. Resource-card interaction feedback changes the border rather than fading text. Card secondary links and footer contact/report links have at least 44px of target height, with spacing between adjacent card destinations. Keyboard focus is visibly outlined on card and footer links; interaction feedback does not reduce text contrast. These shared styles also cover event report links and the blog's contact footer.

The build reads DynamoDB using a scoped AWS role that can scan only the public attributes named in its projection. The Meetup sync role can read only the group and event fields it needs and can write only `meetup-event-*` keys. Visitors do not receive AWS credentials or access the table. The public catalog has no runtime API, database stream processor, or database-to-Git synchronization.

## Preview boundary

The directory preview uses an Amplify default hostname. Before cutover it is excluded from indexing and production Analytics collection. Its contributor form uses the owned API. Blog leads to the local featured cards and complete article archive, and all 196 inventoried article paths are generated locally. The production build enables indexing for content pages and includes community and event country pages in the sitemap. The search utility `/buscar/` remains accessible with `noindex, follow` and is omitted from the sitemap. The Analytics module sends data only when the browser hostname is `dondeaprendoaws.com`.

The site uses owned styles, scripts, and assets. Unicorn's generic client bundle and SEObot's publishing integration are not part of the replacement. Existing articles remain content to preserve, regardless of the tool originally used to write them.
