# Directory behavior

The public directory helps visitors discover Spanish-language AWS learning resources and communities. It displays the approved titles, descriptions, legacy category values, and exact outbound URLs, including their query strings. The build does not invent missing descriptions. The short homepage links to dedicated **Aprender** (`/aprender/`) for individual articles, videos, courses, episodes and tools, **Creadores y canales** (`/creadores/`) for continuing sources such as blogs, channels, podcasts and newsletters, **Comunidades** (`/comunidades/`) for groups and community spaces, and **Eventos** (`/eventos/`). It shows up to four recommended resources and the next three events instead of the full catalog. Existing `/#resource-<id>` and `/#event-<id>` links route to the new page and reveal their card. AWS User Groups and Student Builder Groups are distinct community formats. Kind, format and up to three topics are separate DynamoDB fields. Search and format/topic controls operate in the browser on each resource page; supported filters and sorting are represented in shareable query parameters and restored by browser history. Certification study keeps its exam selector visible before results, alongside sorting and secondary filters; the result counter remains with the results. Results reveal twelve cards at a time with a further twelve per click. All published links remain in the generated HTML without JavaScript. Resource-directory pages stay at or below 2,000,000 raw HTML bytes, a conservative crawl-size bound enforced by site verification; every published card and description remains in the static page.

Directory pages keep their relevant format, topic, or type navigation and a short introduction before the controls. Search and one sort control stay visible outside the secondary-filter disclosure. Where an exam or primary country selector is present, it occupies its own row on narrow screens; sorting shares the next row with the secondary-filter trigger. Applicable secondary facets use a native, closed-by-default disclosure with a positioned panel that does not move the results. Its active count includes only effective facets in that panel: format, topic, country, or level when available there. It excludes search, sort, certification exam, and any primary country selection. A valid secondary filter restored from the URL updates the count without opening the disclosure. Changing a facet inside leaves it open; Escape while focus is inside closes it and returns focus to its trigger. Leaving by focus or clicking outside closes it without taking focus from the visitor's next control. Using the theme toggle leaves the panel open. Without JavaScript, the native disclosure and static directory links remain useful.

`/comunidades/` remains the complete directory, including its legacy `?country=XX` filter and `#resource-<id>` anchors. On the general directory and the two community-type pages, the existing country select is a primary filter for the current result set. The general directory also has a closed native menu linking to national routes; the type pages do not add that route menu. A country page fixes its community subset and offers the native country-route menu without repeating the country filter. At build time, each supported country with at least one published community whose country is known gets a static `/comunidades/<slug>/` page. A fixed country-code-to-slug map keeps these URLs readable and stable; the pages use the same cached public catalog snapshot as the other routes and the sitemap. Each page contains only that country's communities in its initial HTML, with its own title, description, canonical URL, Inicio → Comunidades → country breadcrumb, and a factual summary of its community-format counts, including Student Builder Groups. Search, format and topic filters, sorting, and show-more work within that subset; changing country navigates to another page. The global and country pages include brief FAQs about participating in a community and finding its events, alongside guidance about the community formats. The count summary uses the same published subset as the cards; the result counter continues to reflect interactive filters. Community summaries, longer orientation, and FAQs follow the result list or its empty explanation, while type and country navigation stays available before results. The collapsed native country menu keeps links to generated country pages in the HTML without taking space from results. New internal links to a community use its country page and stable card fragment when country is known; communities without a known country retain `/comunidades/#resource-<id>`. The homepage's older hash redirect continues to target the general directory for backward compatibility.

When visitors reveal more directory results, focus moves to the first newly
revealed card, including the final batch that removes the reveal button. The
next Tab reaches that card’s link. Normal initial rendering, filters, sorting
and restoring URL state do not move focus to a result automatically.

The global `/buscar/` page searches blog articles and published catalog resources together from a static public index generated at build time. It also includes active deduplicated events. Ranking requires every meaningful query word and favors title, topics and article headings over incidental description or metadata mentions; common Spanish connecting words do not skew results. Its query is intentionally not shareable in the URL so Analytics and HTTP referrers cannot carry the typed text; the directory-specific filter URLs remain shareable.

A search submitted with only whitespace clears its prior results and pagination
and shows the empty-query guidance. A previous asynchronous search cannot restore
those results afterward. Revealing more search results focuses the first new
result link; the initial search response leaves the visitor’s focus in place.
The initial public-index download has a bounded wait, including reading its
response body. A stalled or failed download shows the existing retry guidance
and clears the failed request even when its original query is no longer current.
The next submitted search can retry immediately; successful downloads remain
cached for subsequent searches on the page. Only the latest submitted query
can replace results or status.

`/recorridos/` provides four editorial sequences for fundamentals, serverless, security and generative AI. Each step resolves a published learning resource or a blog article to its existing internal destination; it does not copy that content. The paths are also available in global search. See [learning paths](learning-paths.md) for the editing contract.

**Agenda de eventos** at `/eventos/` contains published past, in-progress and future events, sorted by start time. The homepage preview and global search remain limited to upcoming/in-progress events. An event is a published catalog item with `recordType=event`, title, description, `startsAt` and `endsAt` as ISO timestamps with explicit offsets, IANA `timeZone`, organizer, mode (`online`, `in-person`, or `hybrid`), place for physical events, and `registrationUrl`. Only projected public fields reach the page. The agenda initially reveals twelve deduplicated cards, with more available through Mostrar más; all route events and their links remain in the generated HTML without JavaScript.

The compact agenda places its events before extended summaries, national community information and FAQs. Rows are grouped under day headings using the selected representative’s actual start date in the effective schedule zone; an overlapping multi-day event keeps its real start day even when it began before the consulted period. Headings appear only for days with visible occurrences and are not counted as results or repeated by Mostrar más. Each row keeps its full title, start/end time, attendance, relevant physical location and original registration action visible. A native **Detalles** disclosure starts closed and contains the description, organizer schedule, co-hosts, full venue information, calendar, recording when available and report action. Public identities, aliases and original links stay in the HTML.

Every global, national and mode agenda opens with **Incluir eventos finalizados** checked. It remains outside the secondary panel so it is always reachable as the expiry focus-recovery target. The checkbox stays local to the current page session: filtering, clearing, pagination and browser history preserve its current value, while opening/reloading starts checked again. It is not stored or serialized in the URL. `endsAt <= now` means Finalizado; an earlier start with a later end means En curso. The selected cards, count and fact summary update at start/end boundaries and on return to a visible tab without moving focus to a different card. A replacement representative preserves the same occurrence’s expanded-detail state. If it hides the focused member, its equivalent action or detail summary keeps keyboard focus within the same occurrence; the replacement detail opens before an internal action receives focus. When expiry removes the focused card or the focused Mostrar más control, focus returns to Incluir eventos finalizados without changing its value or scrolling the page; unrelated focused controls remain untouched. With the checkbox checked, ending changes the state and original link label to **Ver evento** instead of removing the card. Inscribirme remains for upcoming/in-progress events and is the only action that emits the existing `event_registration_click` with public ID/mode/country; a historical page visit is not counted as a registration. Finalizado describes scheduled time, not proof of attendance or realization.

The complete filtered selection drives the count and summary before pagination. Every agenda opens on the current week, with **Semana / Mes** and previous/next arrows replacing the custom date range. **Semana actual** returns to week view using today in the selected zone, restores the first twelve results, and keeps attendance/location/community, zone, unrelated query parameters and the local ended-events checkbox. Like period arrows it pushes browser history and clears the old fragment. Weeks run Monday–Sunday and months follow the calendar. A public event belongs when any part of its duration overlaps the period in the selected IANA zone: `startsAt < periodEnd && endsAt > periodStart`. An event ending exactly at the beginning is excluded; an event continuing into the period is included. One occurrence can therefore appear in consecutive periods, once in each.

The browser detects the initial zone, falling back to UTC when invalid; **Zona horaria** in Más filtros changes it explicitly. Primary dates, hours, period limits and the next-event summary all use that zone. The organizer schedule remains a separate reference. Both schedules include the end date when it differs from the start date in their respective zone, so a multi-day interval cannot appear to finish on its first day. Calendar navigation uses civil dates, including daylight-saving transitions. A reference `date=YYYY-MM-DD` remains inside the period when switching views or zones; it is not forced to Monday or day one. Month navigation clamps a missing day to the last day of the target month. The current open period stays fixed at midnight and on return to a visible tab.

The URL records `view=week|month`, the concrete reference date and `tz=IANA`, plus attendance mode, physical country/city and an exact public community ID. Browser history restores these values while keeping the local checkbox. Clearing filters keeps period, zone and checkbox and selects combined attendance without location or community. Legacy `from`/`to` opens the week of the first valid date (`from`, otherwise `to`) when no explicit valid date is supplied; the old range is then removed. Malformed calendar input normalizes without breaking the page, preserving unrelated query parameters. Invalid query zones use the detected valid zone, otherwise UTC. A valid location remains represented even when it has no current events; city keys contain country and city to distinguish names such as Córdoba, Argentina and Córdoba, Colombia. City identity ignores accents, letter case and repeated whitespace within the same country, while keeping an original public label. Equivalent city options appear once; old aliases resolve to the equivalent selected option and effective URL without changing catalog facts. A city incompatible with the selected country is cleared. An empty result never silently broadens to all events. A community is valid by its published ID, independently of its country and whether it has matching events.

**Solo online** includes online and hybrid remote participation from every published country. **Solo presencial** includes in-person and hybrid participation at the selected physical location. **Presencial + online** combines local physical attendance with global remote participation, counting a hybrid occurrence once. Location controls stay selected but disabled in Solo online and become active again when switching back. A hybrid included remotely from another location is identified as online participation rather than a local physical event. The legacy `mode=hybrid` query still selects hybrids exclusively; it is not a permanent fourth primary option. Attendance, country and city are primary controls on every agenda; community and zone remain in Más filtros. The effective zone stays visible beside the period even while Más filtros is closed. Secondary filters start closed in every viewport, including active URL selections; their label indicates active community filters without opening automatically on query, history or resize. Controls wrap into readable short rows on mobile.

Stored event `country` remains the organizing community's country, including existing registration Analytics. Optional `venueCountry` describes an explicit physical country as two uppercase ASCII letters, independently of the editorial organizer-country enum. `city` describes the physical event city; a community may also have an optional reviewed public city. One effective-location helper serves grouping, filters, options, cards and event destinations. Physical country prefers venueCountry, then event country, then community country; city prefers the event, then a geographically compatible community city. An explicit foreign venue never borrows the organizer's city from another country. Online events have no physical location. Fallback is derived, never persisted or specially labeled. Cities are not inferred from group names. Unknown city does not imply a match with a particular city. Country labels use Spanish region names when available and otherwise the stored code; adding a venue code does not create a new national route.

The static HTML contains the complete public occurrence catalog on every agenda, with organizer schedules, co-hosts and original links. It initially displays that route's attendance defaults across all dates, with other groups hidden but available for query overrides. Static day headings and primary times consistently use UTC, explicitly identified; the organizer schedule retains its original zone inside Details. JavaScript applies the visitor's period, zone and filters; the no-JavaScript notice explains the initial selection and interactive periods. National and mode routes are editable defaults, not additional hidden predicates. Explicit query fields override them, including `country=` or `mode=` to clear a nonempty route default. Canonical URLs and social metadata remain route-based; query combinations do not create static pages or filtered social previews. A query overriding a route default updates the visible heading, introduction and document title to neutral global copy. Static FAQs describe how to use the route defaults without claiming they always reflect the current query. Native links between agendas preserve period, zone and community; a country destination replaces only physical country and clears an incompatible city, a mode destination replaces only attendance while retaining location, and the global destination keeps the explicit selection. Empty overrides are retained where the destination needs them.

Every agenda provides one **Compartir** disclosure with native X and LinkedIn links and **Copiar**. All three use the same complete, ordered selection and its chosen representative for each occurrence, before pagination. Copy immediately writes `*Agenda eventos AWS, <period>*`, attendance/location context and a readable zone/UTC-offset line, followed by one block per occurrence: emphasized weekday/date/start time, full title, attendance, original registration URL and Finalizado when ended. Ordinary same-day entries need only their start time; multi-day entries preserve the end date/time. The selected zone, rather than the physical filter city, determines schedules and the zone label; differing seasonal offsets are stated when applicable. A selected community adds context only to Copy. A foreign hybrid selected remotely is described as online participation, without suggesting local physical attendance. Empty selections remain shareable with zero events and “No hay eventos que coincidan con estos filtros”. No local preview or intermediate text panel is added.

LinkedIn prepares “Eventos para aprender AWS…” with period and attendance/location context, one line per occurrence, the schedule-zone line, and “Detalles e inscripciones:” followed by the agenda URL. It keeps every title intact while the final body, including line breaks and URL, fits the conservative local limit of 3,000 UTF-16 units. When it exceeds that limit, the entire enumeration is replaced by an explicit total and “La lista completa de eventos, horarios e inscripciones:” plus the URL; it never silently lists only the first few events. Copy remains complete. X prepares “Agenda de eventos para aprender AWS…” with period, count and context, then “Agenda completa e inscripciones:” and the URL. It has no per-event list, extra “Resumen” prefix or schedule-zone line. The full body plus the trailing space observed in X's editor must be valid under twitter-text and at most 280 weighted characters. Only the city may be shortened by grapheme with a visible ellipsis when necessary; the exact city remains in the URL and the other two texts.

The shared URL always targets `/eventos/`, rebuilt with concrete view/date/zone and effective attendance/location/community filters; route defaults become explicit when needed. It drops fragments, unrelated parameters and checkbox state. The recipient always starts with ended events included, so it may show more than a sender who excluded them. It is a live selection over the public catalog, not an immutable snapshot. X Web Intent and LinkedIn share-offsite receive the entire body, including the final URL, through `text` alone; passing a separate `url` would change placement or duplicate the link. Both require the visitor to review and confirm in the network. LinkedIn text prefilling is observed in its authenticated web editor, without a public parameter contract found; continuation after a fresh login and native mobile apps remain unverified. This compatibility limitation does not authorize a manual-copy fallback or account connection. The static global route supplies social preview metadata; filters do not generate separate previews.

Copy confirms success only after clipboard writing resolves. Only Copy is disabled while one write is pending; filters and social links remain available. Missing clipboard access or a rejected write gives a brief honest error and allows retry. A pending write retains the selection captured at the click, and feedback distinguishes it if the visitor changed the query. Compartir, Más filtros and the agenda country menu use native nonmodal disclosures with positioned panels bounded to the viewport. Opening or closing them does not add document height or move the event rows. Escape closes and restores focus to the trigger; Tab/Shift+Tab or an outside click close on exit without stealing focus or altering filters/history. Moving to or activating the theme toggle preserves the panel; leaving the toggle resumes normal dismissal. Selecting a filter inside an open panel keeps it open while updating results. Copy feedback remains visible and announced outside its menu when the menu closes. Share controls stay hidden without JavaScript. Image export and Instagram are not available yet.

The agenda groups complete public occurrences, then chooses a member that satisfies the period, attendance/location, community and checkbox together. When a listing connects existing compatible session and registration groups, those groups and their registration references are reconciled into one occurrence; a weak session match cannot bridge incompatible physical venues. It retains all co-hosts, preferring a matching in-progress/upcoming member over an ended one, then sorting by start/ID. The public contribution form continues to collect resource submissions; hand-curated event records use the checked transaction path described in the operational guide, and Meetup events use the approved sources.
Community options include every published community and never disappear or clear because the physical country changes. All known co-host communities remain in each event card's data even when the event appears as one deduplicated card.

## Content ownership

DynamoDB is the single authoritative resource catalog. Site templates, assets, blog article files and [certification editorial guidance](certifications.md) belong in Git. Certification selections reference published resource IDs; they do not copy the catalog title, destination or publication permission. Approved catalog records are not copied into Git for ongoing editing. The versioned Latin American Meetup directory is a reviewed seed for the initial import; it does not override later edits to the live catalog.

## Creator pages and shared eligibility

Creator profiles do not create a second directory catalog. A profile can show a resource link immediately, including while it is pending directory approval or deselected from the directory. The catalog keeps one shared resource record for a URL and each profile keeps a separate placement with its own order, profile highlight and directory selection. Profile highlights do not set the directory's editorial `featured` field. See [creator page behavior](creator-pages.md) for profile, ownership, moderation and photo rules.

Every resource needs `published=true`, `approvalRevoked` other than `true`, and `hidden` other than `true` to appear in public output. For resources with `directoryControl: creator`, publication also requires at least one selected placement owned by a published, non-hidden profile. This single eligibility projection feeds generated directory surfaces, collections, search, related resources and the publication hash; a profile link alone never adds a record to those surfaces. When more than one profile selects the same resource, the generated directory still contains one catalog card. Removing one selection leaves other selected placements effective. Revoking approval excludes the resource globally while leaving its profile links visible; hiding the resource removes it from profiles too. Hidden profiles return no public page and do not qualify a placement. The admin page records revocation as `published=false` plus `approvalRevoked=true`, so later syncs cannot silently restore that resource; reapproval through the admin page clears the override.

Legacy resources that retain editorial control continue to follow the existing editorial publication rule until an administrator explicitly links them to a creator. A profile reference or claim request does not make that transition. Claim review is manual and binds only the exact resource IDs an administrator selects after reviewing private evidence. Neither program names nor social links are verified or included as separate directory records. Directory snapshots refresh on the hourly publication check and successful Amplify build; the public profile itself is rendered from current service state on each request.

The directory does not accept payments or sponsorships. Recommendations are selected manually by the owner; the `featured` flag records that choice. Only articles in this site's blog are own content. The owner's channels and other resources are ordinary catalog resources and receive the same treatment as other entries. Each resource directory states this policy in its selection explanation and links to the blog. This native disclosure sits below the results and their reveal-more control, including empty-result states, and is closed on initial load. The `#directory-criteria` anchor targets the disclosure itself so a shared URL does not automatically expand its contents; visitors can open it when needed.

The initial migration created 95 supplied entries with the Boolean `published=true`; 12 more were approved later. The type migration classified those 107 records and changed only `kind`, `format`, and `topics`. The original `category` field remains for compatibility, but it does not control the new directory filters. Legacy records without the new fields are classified at build time so they remain visible during migration; incomplete explicit taxonomy is a build error. Reimporting an old export does not overwrite existing records, their content, or their publication flags. The 233 reviewed Spanish-language Meetup groups are imported with distinct IDs and conditional writes, so rerunning their import preserves live edits. Removing a group from the seed does not remove its imported record; revoke its approval in the admin page. The hourly event sync ignores Brazilian and Jamaican groups.

The discovery pass repaired seven empty descriptions and four moved links, and hid one duplicate Spotify listing for the podcast whose own site remains published. The hidden record stays in DynamoDB for review. The 12 resources added on 2026-09-25 have that verified `addedAt` date; older migrated records have no invented date. **Añadidos recientemente** shows only records with a known date. Sorting by recency puts undated records after dated ones. **Recomendados** uses the editorial `featured` flag. Each of the three directories explains in native HTML that **Recomendado** identifies a manual editorial selection. A known `addedAt` appears as **Agregado al directorio** with a Spanish date in UTC; it means incorporation into this directory, not original publication or later update. A missing date stays absent. The country field means the known country of the creator or organizing community, not an AWS region; level applies only to individual learning content. Both fields are optional and are shown only when supported by a source. A level is orientative for the topic and stated prerequisites, not a certification; a missing level is unassigned. An editorial link check establishes reachability at the check time only; it does not certify that instructions remain current, so no permanent verified badge is shown. Resource cards do not publish link-check or content-review dates. Country, level, format and topic filters can be combined.

Optional `sourceId` and `communityId` values point to existing catalog IDs. A displayed **Autor o fuente** relationship can identify an author, channel, or publishing organization through its published source record; it is not inferred from the destination host. When the referenced source or community is published, the content card links to its directory card; a hidden or missing target is not linked. Deep links reveal cards even when another section was selected. The build projects only these public fields and never private contributor contact details.

Only records with a Boolean `published=true`, `approvalRevoked` other than `true`, and `hidden` other than `true` can appear in public output. Missing or false publication flags are unpublished; malformed publication, revocation, or hidden values must not accidentally expose a submission. Public output is constructed from explicit allowlists of resource and event fields, never by serializing a database item that may contain submitter contact details.

The build must consume every scan page using strongly consistent reads so an approval completed before the scan begins is visible. Failed or malformed reads stop publication instead of producing a partial or empty catalog. A successful read with no published entries is a valid empty state. DynamoDB scans are not atomic snapshots of edits made during a multi-page read; a later hourly check can republish a changed hash.

## Publication

The site is a static snapshot. An hourly Lambda hashes the approved public catalog and starts a fresh Amplify build when it differs from the last successfully deployed hash. A second hourly Lambda reads each approved Meetup group's public iCalendar feed and structured data for unsuppressed, non-cancelled entries still observed there, then updates their DynamoDB records. Feed/page failures keep the existing protections for that group's prior events and raise an alarmable error; healthy sources can still update. An incomplete calendar or event block is a feed failure, never evidence of disappearance; a valid empty calendar still permits absence-based retraction of future events. When data changes, the sync invokes the publication checker; its own hourly schedule still handles manual approvals. The hash also includes whether each event has passed its end time, so the next hourly check rebuilds the static page after an event expires without a database edit. Retaining the catalog record does not stop this transition: the homepage and search still remove ended events, while the agenda updates their state and retains them when its checkbox is checked. Published recordings remain available through Aprender and their event cards. A Git deployment also reads the current catalog. Unpublishing follows the same rule; changing the flag does not instantly erase already-deployed HTML or external caches. The publication state lives in the reserved `__system#publication` item of the same DynamoDB table and is not a public resource. The Lambda records the hash only after Amplify reports success, checks for active builds before starting another, and raises an alarmable error when its build fails. An owner can still request an immediate build with `npm run publish`.

Meetup events retain their existing publication permission when their scheduled end passes, including when they subsequently disappear from a healthy feed. `published` authorizes public exposure; `endsAt` determines whether an event has finished. No separate archive or persisted lifecycle state is needed. For an existing ended Scheduled/Rescheduled event, source facts can be refreshed without writing `published`, so neither a hidden historical record nor a concurrent publication edit is restored. A publishable page must have a string name that is nonempty after trimming; an invalid name is a source error before any write, preserving the prior record and allowing healthy sources to update. Explicit valid nonpublishable states do not require a name to retract an event. Unchanged observations do not cause hourly rewrites. An ended event without an existing record is not imported, and previously hidden historical rows are not automatically republished because the old flag cannot establish why they were removed.

Explicit feed/page cancellation, other known valid nonpublishable page statuses, a future event missing from a healthy feed, and removal of its community from approved sources still unpublish events. Explicit cancellation and source removal also apply to historical records. Cancellation-only feeds can omit TZID: their identities are enough to retract prior records without page mapping. Entries that require mapping still need a valid feed timezone. A missing, malformed or unknown page status is a source failure, not a retraction: it reports an error and preserves the existing group protections while healthy groups can still update. `autoSync=false` prevents source edits. Editorial suppression uses the admin page's revoke action, which writes `published=false` and `approvalRevoked=true`; sync preserves and respects this explicit override until an administrator reapproves the event. Writes retain source-ownership and sync guards, and absence-based retraction checks the observed end time to avoid overwriting a concurrent reschedule. There is no global ordering guarantee between simultaneous ingestions. Historical pages no longer exposed in feeds are not all crawled again: this retention preserves known permission and facts, not proof that an event occurred or a complete archive with guaranteed later cancellation detection.

Visitors submit contact details, title, URL, description, kind, format, and optional topics through the owned form. The API validates them, conditionally creates a catalog record with `published=false`, and confirms receipt only after DynamoDB accepts the write. A successful response includes the stable record ID and submission timestamp for the visitor's receipt, but no private contact data. The form explains that publication depends on editorial review; duplicate exact URLs, including pending submissions, are rejected without changing an existing record. The API temporarily accepts the old `Category` payload from already-deployed pages. The record also contains private submitter name and email fields for the owner's review. The build's projection excludes those fields even after approval. Newly approved entries default to order zero and appear after the imported records; the owner can edit their order directly.

The contribution form visibly explains that submitter name and email are stored
for reviewing the contribution and excluded from the public directory. It links
to the existing contact mailbox for requests to delete those details; requests
are handled by the owner, not an automated deletion endpoint. The notice does
not invent a retention period. When JavaScript is disabled, native HTML explains
that it must be enabled to send the form. The normal JavaScript validation,
submission and receipt flow stays available.

Resource and event cards offer a contextual email draft for a broken link or incorrect data. The draft includes only the public title, record ID and destination URL; the visitor must send it from their own mail client. A generic footer link covers pages without a card. This reuses the existing contact mailbox and does not create a second submission or moderation store. Editors investigate these messages and correct the authoritative DynamoDB record, or the versioned article file when the report concerns an article.

Footer text and links remain readable against their background. Resource-card interaction feedback changes the border rather than fading text. Card secondary links and footer contact/report links have at least 44px of target height, with spacing between adjacent card destinations. Keyboard focus is visibly outlined on card and footer links; interaction feedback does not reduce text contrast. These shared styles also cover event report links and the blog's contact footer.

The build reads DynamoDB using a scoped AWS role that can scan only the public attributes named in its projection. The Meetup sync role can read only the group and event fields it needs and can write only `meetup-event-*` keys. Visitors do not receive AWS credentials or access the table. The public catalog has no runtime API, database stream processor, or database-to-Git synchronization.

## Preview boundary

The directory preview uses an Amplify default hostname. Before cutover it is excluded from indexing and production Analytics collection. Its contributor form uses the owned API. Blog leads to the local featured cards and complete article archive, and all 196 inventoried article paths are generated locally. The production build enables indexing for content pages and includes community and event country pages in the sitemap. The search utility `/buscar/` remains accessible with `noindex, follow` and is omitted from the sitemap. The Analytics module sends data only when the browser hostname is `dondeaprendoaws.com`.

The site uses owned styles, scripts, and assets. Unicorn's generic client bundle and SEObot's publishing integration are not part of the replacement. Existing articles remain content to preserve, regardless of the tool originally used to write them.
