# Blog content

The blog promotes AWS learning content through the existing article URLs. Articles live as Markdown files in Git under `src/content/blog/`; Codex can edit those files, but it is not the content store. The index displays six editorially selected articles: Spanish Cloud Practitioner resources, beginner labs, free certification study materials, the beginner AWS guide, AWS for students and educators, and free resources and community. All other articles appear in a dated archive. All 196 article paths remain stable and navigable from the index.

Each article keeps its original publication date and canonical URL. Editorial revisions can update its title, description, body, images, and links while preserving useful social metadata and supported YouTube embeds. HTML blocks are allowed inside Markdown when they preserve tables, figures, heading IDs, embeds, or other source structure. Necessary article and card images are copied into `public/assets/blog/`, so the rendered pages do not depend on Unicorn or SEObot for scripts or media. The static build reads each local image's dimensions and actual format, adds intrinsic dimensions and responsive `srcset`/`sizes`, and emits up to five width candidates without enlarging the source; at the source's natural width it reuses the original URL. It offers a WebP `srcset` only when every same-width candidate is at least 10% smaller than its JPEG/PNG fallback; PNG input uses lossless WebP. Original source URLs remain in the fallback and social image paths stay unchanged. The same build pass covers the site's local partner logo. The blog CSS keeps article images at their natural ratio and reserves the existing crop ratio for cards. The first featured index image loads eagerly; article and related-card images load lazily. Creator links point to the verified original resources. Same-domain links resolve to this site.

The export had no article HTML. For 130 historical articles, body text came from independent pre-cutover web archives; for 51, it came from the then-public pages with the owner's approval. Those 51 bodies have no independent pre-cutover copy for comparison. The original 15 linked articles had retained source HTML.

To edit an article, change its Markdown file and any local images in the same Git change. Frontmatter supplies the title, description, `publishedAt` date, exact `publishedTimestamp` for structured data, local cover/OG image paths, and optional related cards. `indexOrder` controls the featured cards and must use unique consecutive positions starting at 1; other articles appear in the archive, ordered by date. A Git deployment builds a new static snapshot; no CMS or SEObot integration updates the site behind Git.

The production build uses `PUBLIC_PRODUCTION=true` and `PUBLIC_SITE_ORIGIN=https://dondeaprendoaws.com`; it emits indexable pages, a 204-URL sitemap, and one Analytics loader per page. The loader sends pageviews only from `dondeaprendoaws.com`. The Amplify default hostname redirects to that domain, avoiding a second indexable copy. Preview-mode builds, when used separately, carry `noindex` and omit Analytics.

`/buscar/` uses `/search-index.json`, generated in the same build from article titles, descriptions and section headings, the four editorial learning paths, and the approved public catalog fields. Active, deduplicated events are included; expired events are not. The index contains only internal destination URLs and public text. Queries stay in browser memory and are never placed in URL parameters or submitted to a server. Production Analytics receives only search type, query-length range and result-count range, never the query itself. Search results are revealed twenty at a time. The static blog archive and directory pages remain usable without JavaScript.
