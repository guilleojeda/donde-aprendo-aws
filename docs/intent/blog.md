# Blog content

The blog promotes AWS learning content through the existing article URLs. Articles live as Markdown files in Git under `src/content/blog/`; Codex can edit those files, but it is not the content store. The index displays the 15 articles that appeared on the original `/blog/` page, in their original order. The other 181 historical article paths also resolve on the production site, for 196 article routes total.

Each article keeps its title, publication date, description, canonical URL, useful social metadata, substantive body, images, links, and supported YouTube embeds. HTML blocks are allowed inside Markdown when they preserve tables, figures, heading IDs, embeds, or other source structure. Necessary article and card images are copied into `public/assets/blog/`, so the rendered pages do not depend on Unicorn or SEObot for scripts or media. Creator and AWS links keep their original destinations and query strings. Same-domain links resolve to this site.

The export had no article HTML. For 130 historical articles, body text came from independent pre-cutover web archives; for 51, it came from the then-public pages with the owner's approval. Those 51 bodies have no independent pre-cutover copy for comparison. The original 15 linked articles had retained source HTML.

To edit an article, change its Markdown file and any local images in the same Git change. Frontmatter supplies the title, description, `publishedAt` date, exact `publishedTimestamp` for structured data, local cover/OG image paths, and optional related cards. `indexOrder` controls the 15-card index and must be unique for indexed articles; the 181 historical articles have no index order. A Git deployment builds a new static snapshot; no CMS or SEObot integration updates the site behind Git.

The production build uses `PUBLIC_PRODUCTION=true` and `PUBLIC_SITE_ORIGIN=https://dondeaprendoaws.com`; it emits indexable pages, the 198-URL sitemap, and one Analytics loader per page. The loader sends pageviews only from `dondeaprendoaws.com`. The Amplify default hostname redirects to that domain, avoiding a second indexable copy. Preview-mode builds, when used separately, carry `noindex` and omit Analytics.
