# Blog content

Every blog page links to Aprender and Rutas in both desktop and mobile navigation. Articles used by an editorial learning path also identify the path, link to its own `/recorridos/<id>/` page, and offer its next available step after the article body. The continuation uses the same resolved paths and approved catalog snapshot as the route pages, so withdrawing a catalog entry skips it here too. An article may belong to several paths; each is shown. A final article identifies the end of its path rather than inventing another step. Article URLs, content and existing related cards remain independent of this navigation. The index presents guías y tutoriales AWS en español, links to the four learning routes, and retains every article in its featured selection or dated archive.

Both appearances follow the shared [identity contract](identity.md). Astro generates static Shiki highlighting with its `css-variables` theme; the two site palettes own every `--astro-code-*` color. Fenced examples retain their code and token spans; changing appearance does not run a highlighter in the browser or invert editorial images. The content verifier permits the exact shared theme-controller tag also generated in the 404, once in the document head. An identical controller moved into article content, duplicates, altered tags and other executable article scripts remain forbidden; the existing structured-data, navigation-module, Analytics and media rules still apply.

The blog promotes AWS learning content through the existing article URLs. Articles live as Markdown files in Git under `src/content/blog/`; Codex can edit those files, but it is not the content store. The index displays six editorially selected articles: Spanish Cloud Practitioner resources, beginner labs, free certification study materials, the beginner AWS guide, AWS for students and educators, and free resources and community. Each complete title comes before its cover in the linked card; the four learning routes follow the featured choices, while archive and search access remain in the introduction. Featured and related covers are 200px thumbnails with the existing 1.84 aspect ratio. All other articles appear in the dated archive. All 196 article paths remain stable and navigable from the index.

Each article keeps its original publication date and canonical URL. Editorial revisions can update its title, description, body, images, and links while preserving useful social metadata and supported YouTube embeds. HTML blocks are allowed inside Markdown when they preserve tables, figures, heading IDs, embeds, or other source structure. Necessary article and card images are copied into `public/assets/blog/`, so the rendered pages do not depend on Unicorn or SEObot for scripts or media. The static build reads each local image's dimensions and actual format, adds intrinsic dimensions and responsive `srcset`/`sizes`, and offers the standard responsive widths only when each resized file is no larger than the original. Article images also retain the original URL at its natural width, so the largest source resolution remains available. A WebP `srcset` is included only when all offered same-width candidates are at least 10% smaller than their JPEG/PNG fallbacks and no larger than the original; PNG input uses lossless WebP. Original technical body-image URLs remain available. Each article explicitly selects a local editorial cover, shared with its social image; obsolete cover files are retained so earlier public asset URLs still resolve. The blog CSS keeps article images at their natural ratio while featured and related covers use the compact card ratio. The first featured index image loads eagerly; article and related-card images load lazily. Article text, metadata and the 680px reading column remain intact. Creator links point to the verified original resources. Same-domain links resolve to this site.

Each article declares a confirmed `author` ID from `src/data/blog-contributors.json`. The 196 historical articles credit Guille Ojeda (`guille-ojeda`) and link to his public personal profile. That registry stores the public name, Person or Organization type, and an optional confirmed profile URL; the same identity appears in the article header and its BlogPosting data. Original `publishedAt` and `publishedTimestamp` values remain unchanged, and the route fixture protects all 196 original dates and timestamps. An optional `modifiedTimestamp` records the last documented significant editorial change, including a meaningful resource-link repair, with its actual timezone. Builds, template changes and cosmetic edits do not update it. An optional `review` records its documented date, the reviewer ID in `by` when known, and optional context in `note`. Review and modification are independent: neither implies the other, and an unknown reviewer or profile is omitted. The common header labels publication, modification and review separately with semantic time elements; BlogPosting and Open Graph use the exact declared publication and modification timestamps. Content validation rejects unknown identities, invalid calendar dates, inconsistent publication fields and dates before publication. The blog verifier compares every rendered attribution and date with the declared data, preserving the original publication and omitting undeclared modification or review claims.

The export had no article HTML. For 130 historical articles, body text came from independent pre-cutover web archives; for 51, it came from the then-public pages with the owner's approval. Those 51 bodies have no independent pre-cutover copy for comparison. The original 15 linked articles had retained source HTML.

To edit an article, change its Markdown file and any local images in the same Git change. Frontmatter supplies the title, description, `publishedAt` date, exact `publishedTimestamp` for structured data, local cover/OG image paths, and optional related cards. A related card declares only its title and canonical article URL. The build derives its image and alternative from that destination’s cover; a missing destination fails the build. Editorial revisions can change the related selection; verification checks every currently declared card, including its destination, title, cover and alternative, without imposing the historical card count. Each cover has one owner. `coverAlt` describes the image in Spanish and also supplies the social image alternative when the cover and OG image are identical. A different OG image requires its own `ogImageAlt`. Articles emit Open Graph type `article`; general pages use `website` and the owned `site-social.png` card, whose editable vector source is next to it. All pages identify the site and provide matching Open Graph and Twitter image alternatives. `indexOrder` controls the featured cards and must use unique consecutive positions starting at 1; other articles appear in the archive, ordered by date. A Git deployment builds a new static snapshot; no CMS or SEObot integration updates the site behind Git.

The production build uses `PUBLIC_PRODUCTION=true` and `PUBLIC_SITE_ORIGIN=https://dondeaprendoaws.com`; it emits indexable content pages, a sitemap of its public content destinations, and one Analytics loader per page. An article's sitemap entry includes `lastmod` only when it declares `modifiedTimestamp`, using that exact timestamp and timezone, consistently with its visible modification date, BlogPosting and Open Graph. Entries without a documented significant modification, including general pages, omit `lastmod`; publication, review, Git/file timestamps and build times are not substitutes. Rebuilds and catalog updates therefore do not invent article modification dates. `verify:blog` checks rendered dates against the source metadata, and `verify:site` checks every sitemap date against that rendered modification metadata. The loader sends pageviews only from `dondeaprendoaws.com`. The Amplify default hostname redirects to that domain, avoiding a second indexable copy. Preview-mode builds, when used separately, carry `noindex` and omit Analytics.

All site pages serve Fira Sans WOFF2 files from `public/assets/fonts/`, with the original normal 400, 500 and 700 weights and Unicode subsets. The font license and source details travel with those assets. Font declarations are bundled with the site's CSS, so rendering does not wait for Google Fonts CSS or another font origin. Only the Latin regular face is preloaded, since it supplies the introductory text; the remaining faces load when the page uses them. `font-display: swap` keeps text available during loading, and the local fallback uses measured font metrics to reduce movement when Fira Sans arrives. Analytics retains its immediate event queue and asynchronous external script: delaying it further would risk missing short visits, while the measured font bottleneck can be removed independently.

`/buscar/` is a navigation utility: production serves `noindex, follow` and omits it from the sitemap while keeping navigation and search results available. Indexing and link-following directives are independently controlled. Preview builds override page policies with `noindex, nofollow`; the 404 retains that exclusion in production.

`/buscar/` uses `/search-index.json`, generated in the same build from article titles, descriptions and section headings, the four editorial learning paths, and the approved public catalog fields. Active, deduplicated events are included; expired events are not. The index contains only internal destination URLs and public text. Queries stay in browser memory and are never placed in URL parameters or submitted to a server. Production Analytics receives only search type, query-length range and result-count range, never the query itself. Search results are revealed twenty at a time. The static blog archive and directory pages remain usable without JavaScript.

Certification preparation pages own the dated current exam logistics and curated starting points. The two general certification articles link to the complete map and the three supported preparation pages; the Cloud Practitioner resource guide and study plan continue to the Cloud Practitioner page, and the SAA checklist continues to Solutions Architect Associate. These contextual links preserve the articles’ own purpose, original URLs, publication dates and self canonicals. Updated logistics sections keep useful anchors while referring readers to the current exam page. A targeted editorial change records its actual significant modification time without claiming a new publication or a full article review.
